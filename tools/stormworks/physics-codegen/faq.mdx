<AccordionGroup>
  <Accordion title="生成されたコードが文字数上限を超えています">
    Lua 出力パネルの目標文字数の欄の値は目標値であり、生成そのものを止めるものではありません。Lua 出力パネル下部の「local短縮推定」を見て、実際にビークル/マイクロコントローラーに貼り付ける前に手元の Lua minifier で最終的な文字数を確認してください。不要な出力項目のチェックを外す、使っていないオフセットを削除するなどでコード量を減らせます。「local短縮推定」はこのツール自身の簡易シミュレーションであり、実際の minifier の結果と完全には一致しません。
  </Accordion>
  <Accordion title="複数のオフセットに同じ名前を付けるとどうなりますか">
    生成自体は失敗しませんが、2個目以降の名前に `_2` のような連番が自動的に付きます。中央カラム上部の「名前重複」バッジで通知されるので、混乱を避けるため名前は変えることをおすすめします。
  </Accordion>
  <Accordion title="動的オフセットに渡す配列の要素数や順序を間違えるとどうなりますか">
    生成コードは配列の6要素（`{right, up, forward, pitch, yaw, roll}`）をそのままインデックスで読み取るため、要素が不足していたり順序を誤ると `nil` 演算エラーになったり、意図しない値で計算されます。関数の引数の順序は、定義したオフセットの並び順と一致します。
  </Accordion>
  <Accordion title="World Pos が0のまま変化しません">
    Physics Sensor がまだ有効な位置を報告していない可能性があります。「1-3=0位置自動補完」が有効なら、ch1〜3 がすべて厳密に0の間は速度からの積分で補完されますが、それでも0が続く場合は Composite Input の配線（ch1〜3）自体を確認してください。
  </Accordion>
  <Accordion title="ch15〜17直利用を有効にしても Tilt / Compass の値が変わりません">
    この機能は、対象のオフセットが静的かつ回転オフセット（Pitch/Yaw/Roll）がすべて0の場合にのみ適用されます。また直接読み取るのは `Tilt Z`（ch15）・`Tilt X`（ch16）・`Compass`（ch17）だけで、`Tilt Y` は常に姿勢行列から計算されます。動的オフセットや回転のある静的オフセットでは、すべて姿勢行列から計算されます。また ch15〜17 に Tilt センサーなどの出力を実際に配線していない場合、意味のある値にはなりません。
  </Accordion>
  <Accordion title="インポートしたJSONが反映されません">
    インポートするファイルは `settings` オブジェクトと `frames` 配列を含む必要があります。どちらかが欠けている、または JSON として不正な場合はインポートされず、通知でエラーが表示されます。インポートはセーブ管理のツリーではなく、現在編集中の設定だけを置き換えます。
  </Accordion>
  <Accordion title="設定はどこに保存されますか。別の端末と共有できますか">
    編集中の設定とセーブ管理のツリーは、どちらもブラウザの localStorage に保存されます。別のブラウザや端末とは自動で同期されません。持ち運びたい場合は JSON エクスポート/インポートを使ってください。詳細は [セーブ管理と設定の入出力](/tools/stormworks/physics-codegen/reference/data) を参照してください。
  </Accordion>
</AccordionGroup>
