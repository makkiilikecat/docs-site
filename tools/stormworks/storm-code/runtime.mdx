Storm Code は、マイクロコントローラー (MC) 上で動く Lua スクリプトをブラウザ内で実際に実行し、デバッグできます。

## 実行の開始・停止

エディタ上部の実行コントロール (アイコンボタン) から、次の操作ができます。

- **シミュレータ実行 (`F5`)** — シミュレータを実行します。
- **一時停止 (`F6`)** — 実行を一時停止します。
- **ステップイン (1行進める) (`F11`)** — 1 行だけ実行を進めます。
- **停止** — 実行を停止します。

コード上には「▶ Run `関数名()`」という CodeLens が表示され、`onTick`/`onDraw` の実行サイクルとは独立して、任意の関数を単体で実行できます。

## Terminal (ログパネル)

Terminal パネルは、コマンドを入力する対話シェルではなく、実行結果を表示する読み取り専用のログビューです。キーボード入力は受け付けません。実行 (Run ボタンや `scode` コマンド) ごとに 1 つのブロックとして、コマンド行・標準出力/標準エラー・終了コードと実行時間が表示されます。ログは最大 2000 行まで保持され、それを超えた分は古いものから破棄されます。

ログに表示されるコマンド行は、内部で実行される `scode` コマンドです。実行コントロールのボタンや AI がこれらを発行し、その結果が Terminal に記録されます。

```txt
scode run <file>       シミュレータを開始
scode input <ch> <val> Sim I/O の入力チャンネルに値を設定
scode out [<ch>]       Sim I/O の出力信号を取得
scode pause / resume / stop
scode lint <file>      静的解析を実行
scode compile <file>   エントリファイルをコンパイル・minify
scode help
```

## デバッグ

- **ブレークポイント** — 行番号をクリックしてブレークポイントを設定します。実際に Lua VM の実行を一時停止させる本物のブレークポイントで、ファイルをまたいで永続化されます (ファイルをリネームしても保持されます)。
- **ステップ実行** — ステップインのみに対応しています (ステップオーバー/アウトはありません)。
- **コールスタック** — 一時停止中、呼び出し元をたどってフレームを選択できます。
- **変数/ウォッチ** — ローカル変数と、追加したウォッチ式の値を確認できます。テーブルは展開して中身を確認できます。

<Note>
`for i=1,N do ... end` のようなループ変数は、ループ本体に最初に到達した時点ではまだ表示されず、2 回目以降のヒットから表示されます。また `while`/`repeat` の条件式でのみ参照される変数は、名前を持たない一時変数として表示されることがあります。
</Note>

### エラーとクラッシュ

スクリプトが実行時エラーで停止すると、Terminal にエラーメッセージが表示されます。よくあるエラーの種類は次のとおりです。

- `nil` へのインデックスアクセス・関数呼び出し・算術演算・比較・連結
- 不正な引数
- スタックオーバーフロー
- 実行時間の超過 (後述)
- 構文エラー

エラーメッセージの上にある「AI に聞く」から、AI にエラーの内容を説明してもらうこともできます。

## Lua 5.3 エミュレーション

Storm Code の実行エンジンは、実際の Lua 5.3 の C 実装を WebAssembly にビルドしたものです。JavaScript による Lua の再実装ではなく、ゲーム内のマイクロコントローラーと同じ Lua 5.3 のセマンティクスで動作します。

### 使えるライブラリ・グローバル

安全のため、次のグローバルだけが公開されています。

- `pairs` / `ipairs` / `next` / `tostring` / `tonumber` / `type` / `select` / `unpack` / `pcall` / `error`
- `string` (`format` / `sub` / `len` / `find` / `gsub` / `upper` / `lower` / `rep` / `reverse` / `byte` / `char` / `match` / `gmatch` / `pack` / `unpack` / `packsize`)
- `table` (`insert` / `remove` / `sort` / `concat` / `unpack` / `move` / `pack`)
- `math` — 独自に再構築されたサブセットです。`abs` / `ceil` / `floor` / `max` / `min` / `sin` / `cos` / `tan` / `asin` / `acos` / `atan` / `sqrt` / `log` / `exp` / `deg` / `rad` / `fmod` / `modf` / `pi` / `huge` / `random` / `randomseed` は使えますが、`math.tointeger` / `math.type` / `math.ult` / `math.maxinteger` / `math.mininteger` はありません。`random`/`randomseed` は独自の疑似乱数アルゴリズムを使うため、実機の Lua とは異なる乱数列になります。
- `input` / `output` / `property` / `screen` / `map` (Stormworks のマイクロコントローラー API)
- `sim` / `simulator` / `require` (Storm Code 独自の API。詳細は [require とライブラリ](/tools/stormworks/storm-code/require-and-libraries) を参照してください)
- `print`、および `debug.log(message)` のみを持つ簡易版 `debug` テーブル

### 使えないグローバル

`_G` / `io` / `os` / `load` / `dofile` / `loadfile` / `coroutine` / `rawget` / `rawset` / `setmetatable` / `getmetatable` / `collectgarbage`、および本来の `debug` ライブラリは公開されていません。ファイルシステムやプロセスに関わる機能は、ブラウザで動くツールの性質上、意図的に無効化されています。

<Note>
`map.screenToMap` / `map.mapToScreen` は近似実装です。実機の投影と厳密に一致することは確認されていません。
</Note>

## onTick / onDraw のライフサイクル

`onTick` は入力の読み取りと出力の書き込みに使うコールバック、`onDraw` は画面描画に使うコールバックです。どちらも定義しなければ呼ばれません (未定義でもエラーにはなりません)。

- `input.*` / `output.*` は `onTick` の実行中だけ有効です。`onDraw` の実行中に呼び出しても値は返りません。
- `screen.*` は `onDraw` の実行中だけ有効です。`onTick` の実行中に呼び出しても無視されます (エラーにはなりません)。`map.screenToMap` / `map.mapToScreen` はフェーズを問わず計算されます。

### 実行レート

既定では `onTick` / `onDraw` とも 60Hz (実機と同じ) で実行されます。Sim Controls パネルの TPS (Tick/秒) と FPS (Draw/秒) のスライダーで、それぞれ独立して 1〜240Hz の範囲で変更できます。プリセットボタン (`60` / `120` / `Max (240)`) も用意されています。

手動でティックを進める操作もできます。「+1 Tick」「+10 Ticks」のほか、任意のティック数 (1〜10000、既定 60) を指定して進めることができます。「Auto Rerun」を有効にすると、Lua コードの変更を検知して自動的に再実行します。

## Sim I/O パネル

左サイドバーの Sim I/O パネルで、シミュレーション用の入出力・プロパティを設定します。

- **Composite タブ** — チャンネル 1〜32 ごとに、bool 入力のトグル、number 入力の値、bool/number 出力の表示を 1 つのリストにまとめて確認・設定できます。
- **Properties タブ** — キー・型 (`Num` / `Bool` / `Txt`)・値・説明を行として追加・削除・並べ替えできます。
- チャンネルラベルやプロパティ定義は、`sim.lua` という名前のファイルを親フォルダに置くことで、下位のファイルへ継承させられます。対象ファイルからルートまで各親フォルダの `sim.lua` が順に収集されます。継承されたラベルは、由来元のフォルダを示すツールチップ付きで表示されます。

### モニター設定

複数モニターを使う場合は、モニター設定モーダルからサイズ (グリッド単位でのプリセット `1x1` / `2x2` / `3x2` / `3x3` / `5x3` / `8x6`、またはカスタムサイズ) と回転角度を設定します。

<Warning>
カスタムサイズで実際に有効なのは 1 辺 768px (32px グリッドで 24 マス) までです。これを超えるサイズは設定モーダル上では入力できますが、実行時には無視されます。
</Warning>

## 制限値

実行時間・描画コマンド数・ログ出力量などの上限は [リファレンス > 制限値一覧](/tools/stormworks/storm-code/reference/limits) にまとめています。
