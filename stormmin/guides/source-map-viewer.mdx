Storm Min v0.8.0のWeb版では、右側の **Source Map** タブから原文と生成Luaの対応を調べられます。マップの生成と整合性検査にはStorm Lua Engineを使用します。閲覧するだけでLuaが実行されることはありません。

## 現在のLuaを調べる

<Steps>
  <Step title="Source Mapを生成する">
    原文を入力し、右側のSource Mapタブで「生成して調べる」を押します。Source Map生成を有効にして最適化し、検証が成功すると閲覧画面へ切り替わります。通常の「最短化実行」では左の「Source Mapを生成」が有効な場合だけマップを作成します。
  </Step>
  <Step title="左右のコードを選択する">
    生成Luaを選択すると元の範囲を、原文を選択すると生成先の候補を表示します。候補が複数あるときは一覧から選んでください。表示中の候補をハイライトし、選択した候補の対応だけを線で結びます。
  </Step>
  <Step title="理由と関連元を確認する">
    右側に種類・精度・変換名・最適化理由を表示します。関連元やインライン文脈が記録されている場合は、その原文へ移動できます。理由の項目を開くと、記録された適用根拠や判断値を確認できます。
  </Step>
  <Step title="編集へ戻る">
    「編集に戻る」またはOutput / Optimizationsタブを選択します。編集中だったLuaへ戻ります。入力や設定を変更すると、その入力から生成した古いマップの閲覧は無効になります。再度生成してください。
  </Step>
</Steps>

<Note>
  検査中の左右エディタは、生成時の原文と生成Luaを表示する読み取り専用のsnapshotです。検査中に原文のファイルを切り替えても、編集中のLuaは置き換わりません。
</Note>

「対応位置へ移動」を無効にすると、選択に伴う移動を止められます。「対応線」はエディタが横並びで両端が画面内にあるときだけ表示します。縦並びのモバイル画面でも位置対応と理由の確認は利用できます。Monacoを読み込めない場合はテキストエリアで選択し、同じ検査を行えます。テキストエリアでは対応線を表示しません。

## CLIや別のツールで作成した生成物

「生成物を読み込む」には、次のいずれかを選択します。

| ファイル | 内容 |
| --- | --- |
| 生成物JSONを1つ | `kind: "storm-lua-artifact"`、`version: 1`、文字列の`code`と`map`を含むJSON。Engine Playgroundと共通の形式です |
| 生成Luaと`.map`を同時に選択 | 同じコンパイルで作成した2ファイル |

CLIでは `stormmin input.lua -o generated.lua --map generated.lua.map` で作成できます。複数モジュールのビルド成果物も読み込めます。原文ファイルの選択欄から、マップに保存された各snapshotを切り替えます。ファイル名からディスクやネットワーク上の原文を取得することはありません。

読み込んだ生成物は、現在編集中のLuaとは独立したsnapshotとして表示します。読み込みに失敗しても、編集中のLuaや、それまで有効だった検査内容は保持します。

<Warning>
  生成Luaに別の短縮処理をかけたり、改行を変えたりすると、そのマップとは一致しません。組み合わせの違うLua/map、破損したマップ、未対応形式は検証で拒否します。一般的なSource Map v3だけのファイルではなく、Engineの`x_storm`拡張を含む詳細マップが必要です。
</Warning>

## 表示の読み方

| 表示 | 意味 |
| --- | --- |
| `source` | 記録された原文に由来する範囲 |
| `derived` | 原文の構造を変換して作った範囲 |
| `synthetic` | コンパイラが作成した範囲。架空の原文位置へ移動しません |
| `unknown` | 由来が記録されていない範囲。自動生成とは区別します |
| `name` / `token` / `expression` / `statement` / `group` | 対応の精度。広い構文の由来を文字単位の一致とは扱いません |
| `copy` | 同一バイト列として検証されたコピー。区間内部の選択位置も対応します |

例えば`2*3`が`6`へ変わった場合、生成側の`6`は原文の式`2*3`全体に対応します。文字数比で元位置を補間しません。理由の適用根拠が未記録の場合は、その旨を表示します。

`definition`、`callSite`、`argument`、`parameterUse`などの関連元は、変換に関係した原文範囲です。インライン文脈は静的な呼び出し関係であり、実行時のスタックフレームではありません。

エディタ上の行・列は1始まりのUTF-16位置です。詳細の`[start, end)`は終端を含まないUTF-8バイト区間です。日本語・絵文字・CRLFを含む原文でも区別して表示します。

## 除去・置換記録

生成先がない原文には、除去・置換記録がある場合があります。原文の選択範囲で記録を絞り込みます。「全記録」を有効にすると、選択と無関係に全ての記録をページ単位で確認できます。

除去された変数を、同じ関数の括弧や近くの生成行へ結び付けることはありません。置換に関連した元の構文が表示されても、それは実行先やブレークポイントの候補ではありません。EOFや未記録の空白も近隣位置へ寄せません。

## 保存・復元と共有

「生成物JSON保存」は生成Luaとmapを一組で保存します。LuaとMapの個別保存もできます。生成物ファイルは改行を変えず、元のバイト列を保ちます。

同じブラウザでは検査成果物と選択状態を保存し、再読み込み時に再検証して復元します。復元したコンパイル成果物はOutputからも保存できます。処理時間や診断履歴は推測で復元せず、必要な場合は再実行してください。編集中のLuaや設定と一致しないコンパイル結果は復元しません。ブラウザの保存が利用できない場合は警告を表示するため、生成物JSONを保存してください。

ヘッダーの設定エクスポートには、現在の検査状態も含まれます。別の端末でインポートすると、原文や設定とともに検査を再検証して読み込めます。検査を閉じた状態でエクスポートすると、大きなmapは含まれません。

マップには原文全文とPropertyなどの設定が含まれます。公開や外部AIへの共有前に内容を確認してください。[AI Handoff](/stormmin/guides/ai-agent)は編集中のLuaを渡す機能です。読み込んだ別の生成物を調べる場合は、その生成物JSONまたはLua/mapの組を明示的に渡してください。

マップの整合性IDは内容の一致を検査するもので、作成者を保証する署名ではありません。Source Map Viewerはコードの実行・ゲーム内動作の保証・変数値の復元・ブレークポイント設定を行いません。

詳細形式とSDKによる検査は[Engineのソースマップガイド](/storm-lua-engine/source-maps)、生成オプションは[Storm Min API](/stormmin/reference/api)を参照してください。
