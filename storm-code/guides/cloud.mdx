クラウドワークスペースは、サーバーにも複製を持つワークスペースです。
同じ Google アカウントなら、別の端末からも同じワークスペースを開けます。

クラウドワークスペースだけが使える機能:

- 複数の端末からの同期
- [クラウド世代](/storm-code/guides/history) (ワークスペース全体の復元点)
- [メンバーとの共同編集](/storm-code/guides/sharing)
- [Remote MCP](/storm-code/guides/remote-mcp)

## ログイン

Google アカウントでログインします。
Storm Code が受け取るのはアカウントの識別子だけです。

## クラウド化する

`ワークスペース` メニューから、いま開いているローカルワークスペースをクラウドへ上げられます。

ワークスペースの ID と端末内の複製はそのまま維持されます。
**新しいワークスペースが作られるのではなく、同じものがサーバーにも置かれる**形です。

サーバーへの登録と最初の同期が成功してから、一覧上の表示が切り替わります。
途中で失敗した場合に「クラウドにあることになっているが実体が無い」状態にはなりません。

画像も通常のクラウド画像同期に乗ります。

<Note>
  **クラウド化しただけでは、他の人には何の権限も渡りません。**
  他の人を入れるには別途[招待](/storm-code/guides/sharing)が必要です。
</Note>

## 別の端末から開く

ログインすると、選択画面に自分が所有するワークスペースと、
メンバーとして参加しているワークスペースが並びます。ローカルワークスペースも同じ画面に出ます。

一覧は上部の更新ボタンで取り直せます。

<Warning>
  **サーバーの一覧取得に失敗した場合、「クラウドワークスペースが無い」とは解釈しません。**
  警告と再試行できる状態を表示します。
  ここで空として扱うと、既にクラウドに持ち物がある人の画面に、
  意味の無い空のワークスペースが増えてしまうためです。
</Warning>

## 接続が切れているとき

- **本文の編集は続けられます。** 接続が戻ったときに同期されます。
- **ファイルの作成・削除・移動はできません。** `NOT_CONNECTED` として拒否され、
  あとでまとめて実行されることもありません。

ツリーの操作だけ扱いが違うのは、複数の端末が同時に別々のツリー操作をすると
矛盾した状態になりうるため、サーバーが順番を決める必要があるからです。
本文の編集にはその必要がありません。

<Note>
  Service Worker によるオフライン起動は提供していません。
  ページを開くこと自体にはネットワークが必要です。
</Note>

## 自動で反映されるもの

クラウドワークスペースを開いている間、次の変化は手動で更新しなくても反映されます。

- クラウド世代の増減
- メンバーと参加申請の変化
- 一時共有の開始・停止
- MCP の実行ログ

表示している画面の分だけを監視し、閉じれば止まります。
入力中の値やフォーカスが、この更新で失われることはありません。

<Note>
  選択画面はこの自動反映の対象外です。表示したときに1回取得します。
</Note>

## ローカルへ戻す

`ワークスペース` メニューから、クラウドワークスペースをローカルへ戻せます。

サーバー側のワークスペースが削除され、**操作した端末の複製だけが残ります**。
他の端末からは削除されたのと同じことになります。
確認画面には「この端末に残る」「他の端末から消える」の両方が表示されます。

## 上限

| 項目 | 値 |
| --- | --- |
| 1アカウントが持てるクラウドワークスペース数 | 20 |
| ワークスペース1つあたりの本文サイズ | 8 MB |

上限を超えた場合は明示的に失敗として表示します。黙って切り捨てることはありません。
画像の上限は本文とは別に判定されます。

<Note>
  本文が上限に達しても、**既にあるファイルの編集は続けられます。**
  上限に達した瞬間に何も直せなくなるのを避けるためです。
  新しいファイルの追加はできません。
</Note>
